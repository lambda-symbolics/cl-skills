#+title: cl-skills

=cl-skills= discovers, validates, catalogs, and reads reusable agent Skills. It
supports the standard [[https://agentskills.io/specification][Agent Skills]] =SKILL.md= format and a bounded native
=SKILL.sexp= representation. Discovery retains metadata only. Instruction
bodies are read from the selected source on demand.

The implementation targets SBCL on POSIX systems. Filesystem traversal is
bounded, source files must remain regular and root-confined while opened, and
symbolic-link cycles do not cause repeated traversal. A symlinked skill
directory may resolve beneath any configured discovery root; targets outside
all configured roots are rejected.

* Loading

With the system available to ASDF:

#+begin_src lisp
(asdf:load-system "cl-skills")
#+end_src

The library depends on Ironclad, NYAML, ls-compat/posix, sexp-config,
Serapeum, and UIOP.

* Discovering and reading Skills

Roots are ordered. An earlier root wins when several definitions use the same
name. A native =SKILL.sexp= wins over =SKILL.md= in the same directory.

#+begin_src lisp
(let* ((catalog
         (cl-skills:skill-catalog-discover
          (list #P"/home/user/.config/my-agent/skills/"
                #P"/usr/local/share/my-agent/skills/")
          :cache-root #P"/home/user/.cache/my-agent/"))
       (skill (cl-skills:skill-catalog-find catalog "release-notes")))
  (when skill
    (format t "~A~%" (cl-skills:skill-metadata-description skill))
    (write-string (cl-skills:skill-metadata-read skill))))
#+end_src

=SKILL-CATALOG-DIAGNOSTICS= returns non-fatal scan, validation, shadowing, and
limit outcomes. Each diagnostic has =KIND=, =PATHNAME=, =ROOT-INDEX=, and
=MESSAGE= readers. Selected-source failures signal =SKILL-READ-ERROR= or its
=SKILL-BODY-TOO-LARGE= subtype.

=SKILL-CATALOG-RENDER= produces a provider-neutral, character-bounded catalog
containing names, descriptions, and source paths, but no instruction bodies.
It returns the rendered text, included count, and omitted count. Optional
=:PREFIX= and =:GUIDANCE= strings replace the default host protocol sections
and count toward the character budget.

* Validating source text

Use =SKILL-NAME-VALID-P= to check the portable Agent Skills name grammar.
=SKILL-SOURCE-VALIDATE= accepts source text and its intended pathname without
reading or writing files. The exact =SKILL.md= or =SKILL.sexp= filename selects
its format; Markdown names must match the parent directory. It returns the
name, normalized description, and unchanged instruction body. Bind the usual
bounds or supply =:FILE-CHARACTER-LIMIT= and =:INSTRUCTION-CHARACTER-LIMIT=.
Invalid source signals =SKILL-VALIDATION-ERROR= with =KIND= and =PATHNAME= readers.

#+begin_src lisp
(cl-skills:skill-source-validate source #P"release-notes/SKILL.md")
#+end_src

* Source formats

A standard Skill is an exact case-sensitive =SKILL.md= file. It must begin
with YAML frontmatter bounded by exact =---= lines. =name= and =description=
are required. The optional standard fields are =license=, =compatibility=,
=metadata=, and =allowed-tools=. Unknown and duplicate fields are rejected.
The name must satisfy the Agent Skills naming rules and match its parent
directory. The Markdown body is preserved exactly and may be empty.

The native format is an exact case-sensitive =SKILL.sexp= file containing one
data-only form:

#+begin_src lisp
(:autolith-skill
 :version 1
 :name "release-notes"
 :description "Prepare concise release notes."
 :instructions "Read the changelog and summarize user-visible changes.")
#+end_src

Native forms reject reader evaluation, unknown or duplicate fields, improper
structure, excess depth, and excess node count.

* Conversion cache

When =:CACHE-ROOT= is supplied, each validated =SKILL.md= is converted to a
content-addressed native cache:

#+begin_example
<CACHE-ROOT>/skills/agent-skill-v1/<source-sha256>/
  SKILL.sexp
  manifest.sha256
#+end_example

The SHA-256 key covers the exact UTF-8 source. The manifest binds the source
digest to the generated native content. Cache files are published through
same-directory atomic replacement, validated before use, and regenerated from
the standard source when missing, malformed, or corrupt. A changed source uses
a new cache directory.

* Bounds

The exported =*SKILL-...-LIMIT*= parameters control traversal depth,
directories, entries, per-file characters, aggregate discovery characters,
structural native-form complexity, selected instruction size, and rendered
catalog size. Applications may bind them around discovery or selected reads.

* Optional executable Skills

Load =cl-skills/executable= to read an optional, exact =EXECUTABLE.sexp= sidecar
beside a selected Skill source. This system depends on =cl-skills= and
=cl-llm-provider-api/contracts=, whose validator and portable value conversions
are reused. The base system has no executable dependency.

#+begin_src lisp
(:skill-executable
 :format-version 1
 :skill-version "1.0.0"
 :system "release-notes"
 :system-version "1.0.0"
 :entrypoint ("RELEASE-NOTES" "RUN")
 :self-test ("RELEASE-NOTES" "SELF-TEST")
 :verify ("RELEASE-NOTES" "VERIFY")
 :dependencies (("uiop" "3.3.0"))
 :capabilities ("workspace-read")
 :tools ("resource.read")
 :input (:type :object
         :properties (("revision" (:type :string)))
         :required ("revision") :additional-properties nil)
 :output (:type :string))
#+end_src

=:FORMAT-VERSION= must be 1. =:SKILL-VERSION= is a bounded opaque release label.
Declare =:SYSTEM=, =:ENTRYPOINT=, or both. A callable entrypoint requires =:INPUT=
and =:OUTPUT= contracts. Entrypoint, self-test and verification declarations are
exact package-name/symbol-name strings, not reader symbols. =:SYSTEM-VERSION=
is an optional exact ASDF version; dependency pairs declare minimum ASDF
versions. These versions use dotted decimal components. =:CAPABILITIES= and
=:TOOLS= are bounded, duplicate-free string lists, with empty lists as defaults.
Other fields are optional. Unknown and duplicate fields are rejected.

=SKILL-EXECUTABLE-DISCOVER= accepts existing =SKILL-METADATA= and returns an
executable declaration, or NIL when the optional sidecar is absent. Standard
catalog discovery and instruction reading require no executable component.
Executable discovery reads metadata only, without ASDF lookup, code loading,
entrypoint resolution, or authority grants. A malformed existing sidecar signals
=SKILL-EXECUTABLE-ERROR=; the host chooses how to display that diagnostic.

=SKILL-EXECUTABLE-PATHNAME=, =SKILL-EXECUTABLE-DIGEST=, and
=SKILL-EXECUTABLE-MANIFEST= expose the source and declaration. Digest and manifest
readers return independent copies. The digest covers exact UTF-8 sidecar bytes.
Fresh reads enforce root confinement, regular files and stable filesystem
identity. Invocation rejects changed canonical paths, identities, or content,
including changes made during authorization, loading or execution.

#+begin_src lisp
(let* ((catalog (cl-skills:skill-catalog-discover (list skills-root)))
       (skill (cl-skills:skill-catalog-find catalog "release-notes"))
       (executable (cl-skills:skill-executable-discover skill)))
  (cl-skills:skill-executable-invoke
   executable '(:object ("revision" "HEAD"))
   :authorize #'application-authorize-skill
   :loader #'application-load-skill-system
   :context originating-request)
  (cl-skills:skill-executable-verify
   executable :authorize #'application-authorize-skill
   :loader #'application-load-skill-system
   :context originating-request))
#+end_src

=SKILL-EXECUTABLE-INVOKE= accepts executable metadata and portable tagged input,
plus =:AUTHORIZE=, =:LOADER=, =:CONTEXT=, and =:CANCELLED-P= keywords. The entrypoint
receives =(INPUT :CONTEXT CONTEXT)=. The primary result must satisfy the output
contract. Portable values follow the provider contract API: objects are
=(:object ("key" value) ...)=, arrays are =(:array ...)=, true is T, false is NIL,
and null is =:null=. Return values are validated and copied through that API.

The authorization callback receives =(EXECUTABLE :OPERATION OPERATION :CONTEXT
CONTEXT)=. Return exactly T only after approving the declared systems,
entrypoints, required capabilities and tool names. The library requires explicit
authorization even for a declaration with empty requirements. The host must
install and enforce the effective capability set separately, including within
callbacks from worker-host facades.

For declared systems or dependencies, supply a loader receiving =(SYSTEM-NAME
:CONTEXT CONTEXT)=. Register trusted ASDF definitions before invoking, then load
the named system in that callback. ASDF definition lookup occurs after
authorization, with version checks before code loading and afterward. Loading
an ASD can itself execute Lisp, so approve definitions as part of authorization.
Declared dependencies are loaded before the principal system, once per name.

=SKILL-EXECUTABLE-VERIFY= accepts the same callbacks and =:ENTRYPOINT=, defaulting
to =:SELF-TEST=; select =:VERIFY= for the verification entrypoint. That function
receives =(:CONTEXT CONTEXT)= and must return exactly T. Missing declarations,
non-T results and errors signal typed failures. Verification is an explicit
execution result, not an efficacy claim inferred from sidecar metadata.

=:CANCELLED-P= is a cooperative zero-argument predicate checked around major
execution boundaries. The host owns worker isolation, hard cancellation,
timeouts, transport limits and tool policy. Bind the executable character,
node and depth limit parameters to bound sidecar reads and portable invocation
values; defaults are 32768 characters, 4096 nodes and depth 48. Names have a
256-character bound and requirements/dependencies have 128-entry bounds.

=SKILL-EXECUTABLE-ERROR-KIND= and =SKILL-EXECUTABLE-ERROR-PATHNAME= identify failures;
=SKILL-EXECUTABLE-ERROR-CAUSE= retains an underlying condition when available.
Categories include reader and filesystem failures, =:INVALID-VERSION=,
=:INVALID-CONTRACT=, =:IDENTITY-CHANGED=, =:NOT-AUTHORIZED=,
=:AUTHORIZATION-ERROR=, =:LOADER-REQUIRED=, =:MISSING-SYSTEM=,
=:VERSION-MISMATCH=, =:SYSTEM-ERROR=, =:LOAD-ERROR=, =:MISSING-ENTRYPOINT=,
=:INVALID-INPUT=, =:INVALID-OUTPUT=, =:INVOCATION-ERROR=,
=:VERIFICATION-FAILED=, =:VERIFICATION-ERROR=, =:CANCELLATION-ERROR= and =:CANCELLED=.
